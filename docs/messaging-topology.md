### RabbitMQ (asynchronous, Wolverine + durable outbox)

| Exchange | Publisher | Routing keys | Consumers |
|----------|-----------|------|-------------|
| `education.events` | EducationContentService | `material.*`, `issue.*`, `module.*`, `course.*`, `collection.*`, `quiz.*` (`quiz.published`/`access_changed`/`hard_deleted` — ST-11 #490) | ProgressService (exact bindings: `course.created`, `issue.published`, hard-delete material/module/issue/course/quiz; `course.hard_deleted` → cleanup enrollments/grants/bookmarks; **`quiz.hard_deleted` → `QuizHardDeletedHandler`** чистит `quiz_attempts` + `module_item_progress(item_type=QUIZ)`, ST-13 #493), FileService (hard_deleted + `course.asset_ownership_changed` asset projection), EducationContentService internal (content-access sync for materials + collections), SearchService (36 exact handler-backed lifecycle bindings for course/module/material/project/issue/collection → Typesense, including `issue.access_changed`; no quiz/generic wildcard traffic), CommentService (exact hard-delete bindings material/course/issue/quiz), NotificationService (`material.published`, `issue.published` → уведомление подписчикам курса; `course.created` → pre-populate subscriptions для LIFETIME_ALL grantee'ов автора, issue #80), **MaterialProcessingService (`material_processing.education.cleanup`):** `MaterialHardDeletedHandler` сносит content-job'ы материала (transcript + timecode-job'ы остаются на video-asset'е). |
| `file.events` | FileService | `file.bound.*`, `file.deleted.*` | EducationContentService (material/course media), **MaterialProcessingService (`material_processing.file.cleanup`):** `FileAssetDeletedVideoHandler` каскадно удаляет транскрипт и оба job-таблицы для удалённого video-asset'а (фильтрует по `UsageType in {material_video, course_video}`). |
| `auth.events` | AuthService | `user.created`, `user.logged_in`, `user.username_updated`, `user.github_login`, `user.telegram_linked`, `user.telegram_unlinked` | ProgressService (user projection only — без auto-enroll), AccessService (`access.auth.github_events`: мэтчит orgs против plans с `github_org_slug` → PlanGrant — issue #65/#69), NotificationService (welcome on telegram_linked), TelegramBotService (telegram_unlinked → cleanup UserLink; telegram_linked → re-trigger F1 invite DM) |
| `progress.events` | ProgressService | `issue_submission.approved`, `issue_submission.changes_requested`, `issue_submission.awaiting_review`, `issue_submission.author_help_requested`, `user.leveled_up` (#555 — повышение gamification-уровня) | AssignmentReviewService (`assignment_review.progress.submission_awaiting_review`): `IssueSubmissionAwaitingReviewHandler` создаёт AiReview под GitHub PR submission, публикует `AiReviewQueuedForSubmission`. Issue #15 Phase 8. NotificationService (`notifications.progress.submission_events`): review-нотификации автору/студенту + `issue_submission.author_help_requested` (#383) → `IssueSubmissionAuthorHelpRequestedHandler` шлёт автору `AuthorHelpRequested`-уведомление «Студенту нужна помощь» (студент нажал «Позвать автора»). **NotificationService (`notifications.progress.gamification_events`):** `UserLeveledUpHandler` (#555) на `user.leveled_up` шлёт самому пользователю поздравление `UserLeveledUp` (InApp + Telegram; фронт поверх показывает модалку с конфетти). **(`course_enrollment.created/revoked/restored` сняты в access-derive-model Phase 4 #367 — enrollment'ы стали lazy progress-anchor'ами без cross-service сигнала; доступ/уведомления/подписки целиком grant-driven.)** |
| `tag.events` | TagService | `tags.added_to_entity`, `tags.removed_from_entity`, `tags.deleted`, `tags.merged`, `tags.updated`, `tags.alias_removed` | SearchService (tag canonicalization into search docs) |
| `notification.events` | NotificationService **+ TelegramBotService** | `notification.created`, `notification.read`, `notification.broadcast_requested`, **`notification.telegram_delivery_recorded`** (publisher — TelegramBotService) | NotificationService self (SSE fan-out + Telegram delivery tracking), TelegramBotService |
| `comment.events` | CommentService | `comment.created` | NotificationService (`CommentReplied` + `CommentOnOwnContent` notifications) |
| `access.events` | AccessService | `plan_grant.created`, `plan_grant.revoked`, `plan_grant.expired`, `plan_course.bound`, `plan_course.unbound`, `plan.hard_deleted`, `trial.expiry_approaching` (#580 — `TrialExpiryReminderSweeper` за ~5 дней до истечения trial-гранта) | AccessService self-consume (`access.content_access.sync`): writes plan-grant tags to Redis (`plan:lifetime:author_{X}` for LIFETIME_ALL, `plan:course:{id}` for COURSES); on expire — actively removes the same tags. **(ProgressService `progress.access.grant_events` queue + `PlanGrantCreatedHandler`/`PlanGrantRevokedHandler` удалены в access-derive-model Phase 4 #367 — enrollment'ы больше не материализуются на grant, создаются лениво при engagement'е.)** AccessService self-consume (`access.plan_onboarding.grant_events`): `PlanGrantCreatedOnboardingHandler` создаёт `user_plan_onboardings` row если у плана `plan_onboarding_flows.is_enabled=true` (issue #68). NotificationService (`notifications.access.grant_events`): `PlanGrantReceivedHandler` создаёт одно plan-grant уведомление, `SubscribeOnPlanGrantCreatedHandler` fan-out'ит подписки на покрытые курсы (per-course `CourseEnrolled`-уведомления больше не существуют — handler снят в Phase 4 #367), `PlanGrantAuthorSaleHandler` (#428) уведомляет АВТОРА плана о новом участнике с данными покупателя (имя/ник/email; пропускает `Source=MIGRATION` и self-grant). **TelegramBotService (`telegram_bot.access.grant_events`):** `PlanGrantCreatedTelegramHandler` (F1) шлёт invite DM в bound chats плана, `PlanGrantRevokedTelegramHandler` (F6) auto-kick'ает на revoked + expired (issue #65). **EducationContentService (`education_content.access.plan_course_events`):** `PlanCourseEventsHandler` инвалидирует HybridCache `access:plan-for-course:{CourseId}` на `plan_course.bound` / `plan_course.unbound` — обеспечивает realtime обновление цены в каталоге. **TelegramBotService (`telegram_bot.access.plan_deleted_events`):** `PlanHardDeletedTelegramHandler` на `plan.hard_deleted` отвязывает (удаляет) chat_binding'и полностью удалённого плана (issue #417). **NotificationService (`notifications.access.trial_reminder_events`):** `TrialExpiryApproachingHandler` на `trial.expiry_approaching` (#580) напоминает пользователю доплатить до полного доступа (InApp + Telegram, deep-link `/pricing`). |
| `telegram.events` | TelegramBotService | `chat_binding.bound_to_plan`, `chat_binding.unbound_from_plan`, `chat_member.confirmed` | AccessService (`access.plan_onboarding.telegram_events`): auto-sync TELEGRAM step в onboarding flow — на bind ensure'ит, на unbind removes (если flow.IsEnabled). Issue #68. **AccessService (`access.plan_onboarding.telegram_member_events`):** `ChatMembershipConfirmedHandler` на `chat_member.confirmed` (publish'ится `ChatJoinRequestHandler` после approve'а join-request'а в bound chat) auto-complete'ит TELEGRAM onboarding step для (user, plan). Epic #397. |
| `assignment_review.events` | AssignmentReviewService | `ai_review.iteration.completed`, `ai_review.queued_for_submission`, `vcs_installation.created`, `ai_review.oversized_skipped` (#546), `student_pr_question.asked` (#713) | ProgressService (`progress.assignment_review.denorm`): `AiReviewIterationCompletedHandler` обновляет 4 denorm-поля (LatestAiVerdict, AiIterationsCount, LastAiIterationAt, AiReviewStatus); `AiReviewQueuedForSubmissionHandler` гейтит `ReadyForHumanReview=false` чтобы автор не видел submission в inbox'е до Finalize. Issue #15 Phase 8. **AccessService (`access.plan_onboarding.vcs_events`):** `VcsInstallationCreatedHandler` auto-completes `GITHUB_REVIEW_APP` onboarding step во всех active onboardings юзера (issue #307). **NotificationService (`notifications.assignment_review.review_events`):** `AiReviewOversizedSkippedHandler` на `ai_review.oversized_skipped` (#546) шлёт автору курса уведомление «Большой PR — запустите AI-проверку вручную» (InApp + Telegram, deep-link на `/author/review`). **#713 (двусторонний диалог по PR):** ARS публикует `student_pr_question.asked` при reply/комменте студента-владельца PR (webhook `pull_request_review_comment` / `issue_comment` в `HandleGitHubWebhook`, идемпотентно по `github_comment_id`). Consumers: ProgressService (`progress.assignment_review.denorm`) `StudentPrQuestionAskedHandler` пишет `student_question_at` денорм на `IssueSubmission` (бейдж «новый вопрос от студента» в панели проверки); NotificationService (`notifications.assignment_review.review_events`) `StudentPrQuestionAskedHandler` уведомляет автора курса (InApp + Telegram, deep-link `/author/review`). Ответ автора постится reply'ем в PR-тред через ARS `POST /assignment-review/student-messages/{id}/reply`. |
